# OntoFlow v1.4.0 · 用户建模意图、证据分层与 Word 上下文

本版在 **v1.3.10** 的完整工程上实施，不是新建独立系统。主目标是把「怎样读文件」「原文说了什么」「模型提出什么建议」「用户决定怎样建模」分开，不要求用户先按 BC 示例重排文档。不声称已经能无误理解任意业务文档。

## 1. 用户能看到的变化

### 建模意图与用户决定

右侧「本体协商助手」新增 **建模意图与用户决定**，也可以从「理解与主题」页进入。可以保存：本轮目标、明确纳入/排除的类型、角色策略、人工补充术语、理解模式、决定理由。所有修改有版本与历史记录，页面操作同步进入对话。

- 原文与人工补充要求分开保存，不用用户的选择反过来伪造原文。
- 自然语言目标/补充要求传给语义模型。明确的类型名单按名称匹配；程序不假装能够仅靠关键词完整理解任意自然语言范围。
- 角色可以选择「先询问」「优先复用自然人，通过关系表达角色」「允许提出独立角色类型」。任何继承都仍需单独审核，不自动写 `parentId`。
- 自动模式对明确结构采用规则，对歧义保留语义文本；语义复核模式可要求模型复核非原生本体的表格/章节。没有启用模型时，明确显示需要人工/模型核查，不伪装调用成功。原生 JSON 的身份/结构校验仍采用确定性路径。
- 每个候选标识 **原文明示 / 建模推断 / 用户决定**。显式定义不等于事实已核实；模型推断即使提供引文，也不能自行升级为「原文明示」。表格内的李某被抽象为自然人时，同样标为推断，不冒充原文直接定义的类型。历史候选缺少来源分类时显示历史状态，不倒推伪造分类；保存新意图后，它们也必须人工复核或重新生成。

### 意图变化后的安全行为

保存新范围或用户决定会增加本体修订，使旧发布授权不再适合直接重用，但不自动改写任何已审核对象。

- 在旧意图下生成的待审候选标为「需复核」，不能直接批量接受。
- 可以重新生成，或通过「按当前意图复核」记录人工意见；复核仅更新依据，**仍须单独接受**才进入草稿。
- 旧任务在语义请求返回后也要再次核对意图/分支指纹，不能将旧上下文答案提交到新目标。
- 已审核本体、OpenMind 只读基线、UUID/CODE、批量部分成功、零采纳继续、同步冲突处理均保留。

## 2. 文档格式和上下文

### Word 修复

`.docx` 现在按 OOXML 正文实际顺序读取段落、表格及内容控件，并保持标题层级。标题样式及自定义样式继承可以形成章节上下文，普通加粗文字不会被冒充成可靠的标题。

例如：

```text
设备的属性定义
  [设备字段表]
自然人的属性定义
  [人员字段表]
```

这两张表不再先被移到文末，也不会把「表格 1」「表格 2」当作所属实体。没有明确归属、只有说明段落时，保留前置文本和完整表头，交给语义理解/人工选择，不能猜归属。

合并单元格、不等列和嵌套表格保留可读文字并提示结构边界。页眉/页脚、脚注/尾注、文本框保留独立位置，不将浮动位置当作业务归属；修订标记提示用户核查。检测到图片时**不自动执行 OCR**，明确标为未核实部分。不提供不可靠的 Word 页码，使用正文块/表格等定位。

### 材料阅读边界

「查看材料阅读边界」显示实际可读单元、结构特征、示例/建议用语提示及解析警告。结构观察仅作提示，不等于确定文档业务类型。存在图片或版式未核实部分时，概要和任务均不能声称全文覆盖；成功的文字片段仍可先生成候选并供审核。

此版没有替换全部格式读取器。旧 `.doc` 仍依赖可选解析组件；任意截图、复杂版式、格式错误文件等不保证可直接完整提取。

## 3. 分层缓存与性能

沿用 PostgreSQL `extraction_cache`，使用相互独立的版本键：

| 层 | 键与用途 |
|---|---|
| 原文证据层 | 内容哈希、读取结构、章节、前置上下文、来源区域、解析算法版本；可跨建模目标复用 |
| 建模建议层 | 原文键 + 模型/提示版本 + 工作空间、目标、范围、角色策略、用户决定、目标 OpenMind 分支及基线指纹 |

原始资料一样，不代表用户本次想建的本体一样。换目标/范围后不直接复用旧语义建议；规则识别和原文证据仍可以复用。新结果独立于旧版缓存，不自动删除旧缓存或旧审核结果。

完成任务显示实际模型请求、原文缓存命中、当前意图建议缓存命中。指标缺失明确提示，不把未记录说成零请求。

自由文字目标不是一套通用本体推理器。只有模型实际收到语义片段时才会基于这些文字进行理解；纯结构化自动提取仍保留明确原文候选，精确纳入/排除规则和人工审核决定最终范围。

## 4. API 与数据库

新增接口：

- `GET/PUT /api/projects/{pid}/modeling-context`：带 `expected_version` 的意图保存与历史读取。
- `GET /api/projects/{pid}/understanding`：材料结构观察、阅读警告与当前意图。
- `POST /api/projects/{pid}/proposals/{qid}/recheck-intent`：`expected_revision` + 人工说明，旧候选显式复核，不自动接受。

新增表：`modeling_contexts`、`modeling_decisions`、`proposal_origins`，以及对应索引。**Schema 升级为 1.4.0，必须先备份数据库。** 没有重建现有业务表，也不清空工作空间或改写已有原生对象。

定向重试兼容旧检查点：同一来源、同一问题在用户明确授权重试时，即使缓存命名空间改变，也复用原缺口 ID 和处置历史；真正不同的问题仍分开记录。

## 5. 实测结果与范围

- v1.3.10 原包基线：320 通过、5 项真实 PG 测试跳过。
- 本版全量回归：**354 通过、5 跳过、0 失败**，包含新增 **34 项**任意输入/上下文/意图/来源隔离测试。
- 原有断言仅调整明确发生的 Schema 版本（1.3.10 → 1.4.0）；未改变 BC/JSON 核对清单或让错误匹配通过。
- Chromium 执行实际前端 JS，通过进程内 TestClient 桥接临时后端：意图保存、来源显示、排除名单、旧候选复核入口均通过，无 JS 错误。浏览器无外部服务请求，不冒充真实部署网络联调。
- 从冻结 v1.3.10 原包读取旧 SCHEMA，在临时 SQLite 建库后执行新版本初始化：旧工作空间、实体 ID、CODE 均保留，重复初始化幂等。
- 原 BC 文档回归：22 类实体、283 项独立属性目录、373 条挂载、48 条关系，10 个类型问题/4 个部分覆盖单元仍保留；离线规则路径 LLM 请求 0。
- 原生 JSON/ZIP 回归：20 类实体、137 项独立属性、183 条挂载、10 条原生关系加 15 条继承；同分支新增 0，未绑定独立属性仍作为问题保留；离线模型请求 0。

新样例采用图书/馆藏、普通设备、字段歧义、示例草案和人物角色等合成资料。Word/Markdown 同义内容对照和“相同材料，不同建模目标”检查为本地回归，不是未知真实业务样本准确率评估。测试中的模型为可控模拟响应，用于验证调用参数、缓存隔离和语义来源校验，**不能据此声称真实模型理解能力已通过验收**。

当前环境没有 Docker/真实 PG/psycopg，也没有用户 OpenMind 或模型账号。5 个 PG 集成测试跳过，不计为通过。生产并发/DDL/远端写入和实际模型质量仍需现场验证。未引入新的内部 Key 或服务白名单；Demo 只能用于可信环境。

## 6. 两目录升级（从 v1.3.10）

先确认源目录是新包、目标目录是原运行工程，不能调换。保持原 Compose 项目名、`.env`、上传卷及 PG 密码。

```bash
SRC="/新版解压目录/ontology-workbench"
DST="/当前运行目录/ontology-workbench"

test -f "$SRC/app/version.py" && test -f "$DST/.env" || exit 1
cd "$DST" || exit 1
docker compose config -q || exit 1
docker compose stop ontology worker

umask 077
mkdir -p "$HOME/ontoflow-backups"
BACKUP="$HOME/ontoflow-backups/pre-v1.4.0-$(date +%Y%m%d-%H%M%S).dump"
docker compose exec -T postgres sh -c \
  'exec pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > "$BACKUP" || exit 1
test -s "$BACKUP" || exit 1
docker compose exec -T postgres pg_restore --list < "$BACKUP" >/dev/null || exit 1

# 不要使用 --delete，不覆盖配置、原文或数据库备份。
rsync -av --exclude='.env' --exclude='data/' --exclude='uploads/' \
  --exclude='.git/' --exclude='__pycache__/' --exclude='*.dump' "$SRC/" "$DST/"
docker compose up -d --build --no-deps --force-recreate ontology worker
docker compose ps
docker compose logs --tail=100 ontology worker
curl -fsS http://127.0.0.1:8001/api/health
```

应显示 `1.4.0-demo` 和当前 `build_id`。浏览器强制刷新。旧 Word 需「重新解析原始文件」才能使用新正文顺序；随后重新确认概要/主题。已有审核对象不会自动重建。

不要运行旧环境的首次初始化脚本，不要 `docker compose down -v`。回滚使用匹配的旧代码、数据库与上传备份，不能只替换旧源码忽略新元数据。
